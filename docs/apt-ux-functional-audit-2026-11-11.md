# 아파트맵 탐색 기능 전수 점검
2026-11-11 · 코드 브랜치 `fix/map-search-navigation-ux-20261111` · 대상 `public/apt-map.html`

## 원칙
화면 색상이나 디자인 재작업이 아닌 **검색 → 지도 탐색 → 가격대 비교 → 상세 → 복귀**의 동작 일관성을 검사했다. 시세, 데이터 원본, 평가 비중, 점수, 순위 로직은 건드리지 않았다. 저장소의 기존 master를 기준으로 UX 코드를 격리해 수정했다.

## 발견 및 처리
| 범위 | 확인한 문제 또는 위험 | 처리 |
|---|---|---|
| 검색과 지도 | 검색어가 지도 핀을 독점해 이웃 단지가 보이지 않음 | 목록 검색과 지도 표시 조건 분리. 일치 단지만 파란색 강조 |
| 지도 이동 | 지역 이동 후 다른 동네에서도 옛 검색어가 유지됨 | 지도 클릭, 드래그, 수동 확대/축소 시 검색 해제 후 지도 범위의 목록 표시 |
| 가격 탭 | 가격대 변경 시 기존 지도 위치와 줌 초기화 | 중심 좌표와 확대 수준을 URL로 전달. 전용 검색과 가격 필터는 새 탭으로 강제하지 않음 |
| 지도 핀 | 화면 밖 상위권 단지 때문에 표시 한도가 소진됨 | 현재 화면 안에 들어온 후보만 개수 제한에 반영 |
| 지도 초기화 | 카카오 지도 최초 범위 적용이 이벤트 등록보다 빠르면 첫 핀이 나타나지 않을 가능성 | 초기 렌더링을 명시적으로 호출 |
| 지오코딩 완료 | 최초 데이터 위치 확인이 늦게 끝나면 탐색 중이던 지역으로부터 지도가 초기 범위로 되돌아갈 수 있음 | 수동 이동/검색/선택/홈 복귀 의도를 판별해 완료 처리 분기 |
| 넓은 검색 | 유명 브랜드 검색 결과가 수도권에 분산되어 지도 전체가 과도하게 축소될 수 있음 | 분산 범위가 큰 검색은 지도 위치 유지 |
| 검색 지우기 | 검색에서 전체 탐색으로 바로 복귀하기 어려움 | 입력창 검색어 삭제 버튼과 지도 기준 탐색 복원 |
| 검색 결과 없음 | 이유와 해결 수단이 없음 | 검색 없음, 지도 영역 없음, 필터 조건 없음에 따라 문구·초기화 동작 구분 |
| 모바일 키보드 | 지도/하단 패널 조작 중 검색창 포커스 지속 | 지도 및 바텀시트 조작 시 검색 입력 포커스 해제 |
| 모바일 시트 | 가로 스와이프가 시트 세로 드래그로 잡힐 수 있음 | 제스처 방향 판별 후 가로 필터의 기본 스크롤 허용 |
| 모바일 크기 | 화면 회전 또는 키보드로 높이가 작아지면 스냅 지점이 음수가 될 수 있음 | 스냅 높이 하한 적용, 반응형 전환 시 갱신 |
| 목록 상태 | 데이터 갱신 및 지도 탐색 중 스크롤과 필터 가로 위치가 초기화됨 | 자동 갱신 때 위치 유지, 수동 필터 변경 때만 결과 처음으로 이동 |
| 상세/뒤로가기 | 이전 목록 위치 및 단지 URL 해시 관리가 불안정 | 상세 진입 전 목록 위치 저장, 복귀 시 복원, 상세 종료 시 해시 정리 |
| 공유 링크 | 잘못된 퍼센트 인코딩 해시로 자바스크립트가 중단될 수 있음 | 디코딩 오류를 안전하게 처리 |
| 키보드 이용 | 목록 행과 지도 핀이 클릭에만 반응함 | 포커스와 Enter/Space 지원, 접근성 이름 추가 |
| 불필요한 상태 갱신 | 지도 이동 중 이미 탐색 모드인데도 목록을 반복 재구성할 수 있음 | 모드 전환 때만 목록 초기화 |
| 지도 개수 문구 | 안내문이 지도 확대 버튼 영역을 차지할 수 있음 | 안내문 최대 너비 제한 |

## 수행한 검증
1. `node scripts/test-apt-map-ux.mjs` 통과. 모든 인라인 스크립트 문법과 URL 좌표 복원, 잘못된 좌표 거부, 검색 분리, 수동 확대, 관련 회귀 조건을 검증.
2. 모의 지도 단지 2,010개에서 화면 밖 높은 점수 단지 2,000개가 화면 내부 핀의 표시를 막지 않는지 검사. 검색 단지 강조와 인접 단지 동시 표시 확인.
3. Vercel Sandbox의 Node 24 환경에서 `npm ci`, `npm run build` 통과. 여섯 가격대 탭(6, 10, 15, 20, 25, 30억)의 모바일 크롬 자동화에서 목록 로딩 확인.
4. 모바일 크롬에서 실제 목록 검색('하이어스'), 결과 없는 검색, 초기화, 목록에서 Enter로 상세 진입, 브라우저 뒤로가기/상세 복귀 흐름 확인.
5. 카카오 지도 동작을 흉내 내는 브라우저 테스트에서 검색 핀과 주변 핀 동시 표시, 지도 드래그 시 검색 해제, 현재 영역 목록, 전체 지역 복귀, 사용자 확대 시 탐색 전환을 확인.
6. 6~10억 탭의 단발성 느린 최초 로딩이 1회 관찰됐으나 같은 테스트의 후속 반복에서는 약 2초대. 다운로드 파일 지속적인 실패나 일관된 20초 지연은 재현되지 않았음.

## 남은 실제 환경 확인
- 개발 서버 로컬 주소는 카카오 지도 키에 등록된 서비스 도메인이 아니어서 실제 카카오 타일 지도를 직접 시험할 수 없었다. 위 지도 인터랙션 검증은 브라우저 내 카카오 API 모의 구현을 사용했다. 실제 지도 이동과 두 손가락 확대는 등록된 운영 도메인의 안드로이드 크롬에서 추가 확인해야 한다.
- 브라우저 자동화는 실제 키보드가 열리는 안드로이드 기기 실측을 대신하지 못한다. 하단 시트의 실기기 제스처 판정도 최종 확인 항목.
- 로컬 실행의 `/_vercel/insights/script.js` 404는 로컬 환경에서 Vercel Analytics 스크립트가 제공되지 않아 발생한 것으로, 지도나 목록 로딩 실패는 아니다.

## 회귀 방지
검색, 위치, 수동 확대, 필터, 상세, 가격대, URL을 한 화면의 독립 기능이 아닌 하나의 사용 흐름으로 테스트한다. 탐색 기능 수정 후에는 **6개 가격대 로딩 + 검색 후 지도 이동 + 탭 왕복 + 상세/뒤로가기**를 최소 회귀 시나리오로 실행한다.
