# 아파트맵 초기 로딩과 화면 멈춤 개선

점수식과 입력자료는 변경하지 않았다. 기존 f0ebefd와 같은 시세 및 좌표 자료로 6개 가격대 전체의 가격, 순위, 점수, 세부 점수와 상세 계산값을 비교했다. 5,822 / 2,819 / 1,997 / 1,128 / 558 / 255개 평형이 모두 일치했다. 동기 계산과 나눠 실행하는 계산의 결과도 일치했다.

## 변경

- 원본 `public/apt-map.html`에서 배포 시 `apt-map-fast.html`과 내용 해시가 붙은 공통 스크립트를 생성한다. 모든 파일의 실행 순서를 유지하며, 중첩된 투자포인트 스크립트 의존성까지 포함한다.
- 6억 초과 탭의 자체 스크립트 요청을 41개에서 9개로 줄였다. 지도 업체 스크립트는 이 개수에서 제외한다. 6억 이하 탭은 6개다.
- 다섯 상위 가격대는 9개 주소 중 7개를 공유한다. 고정 자료는 내용이 바뀔 때 주소도 바뀌며, 해당 주소만 1년 캐시한다. 매일 바뀌는 `apt-live.js`와 외부 좌표 `apt-geo.js`는 묶지 않고 기존 갱신 주기를 유지한다.
- 자료 다운로드가 HTML 해석을 막지 않도록 defer로 불러온다. 이용 안내와 가격대 이동은 자료 로딩 전부터 작동한다. 글꼴도 첫 화면을 막지 않게 하고 지도 SDK 다운로드는 미리 시작한다.
- 첫 계산은 약 12ms 실행 후 브라우저에 제어를 돌려준다. 단일 계산 단계와 마지막 정렬은 이 시간을 넘을 수 있다. 이후 좌표 갱신에 의한 동기 재계산은 그대로 유지한다.
- 가격대 링크의 불필요한 `/apt-map.html` 리다이렉트를 제거한다. 자료 파일 실패 시 오류를 표시하고 불완전한 순위 표시를 중단한다.

## 검증

`node scripts/test-apt-loading.mjs <before-root> <after-root>` 실행 결과는 같은 폴더의 JSON에 기록했다. 모든 가격대의 정확한 일치, 묶음의 결정성과 재빌드 가능 여부, 실시간 자료의 분리, 비동기 계산 결과를 검사했다. 이 JSON의 실행 구간 측정은 VM에서 재계산한 값이며 휴대폰 접속시간이 아니다.

로컬 Chrome에서 6~10억 탭의 검색과 상세 투자포인트, 10~15억 및 6억 이하 이동을 확인했다. 같은 로컬 환경에서 자료가 준비된 반복 방문의 목록 준비 시간은 수정 전 1,544ms, 수정 후 1,504ms였다. 관찰된 가장 긴 메인 스레드 작업은 749ms에서 296ms로 줄었다. 이 값은 한 번씩 측정한 개발 환경 결과이며 모바일 또는 실제 인터넷 다운로드 속도의 보장은 아니다. 첫 로딩의 미캐시 상태에서는 수정 후 1,873ms였다.

`npm run build`로 Next.js 프로덕션 빌드 성공. 실제 서비스의 지도와 캐시 응답은 배포 후 별도로 확인한다. 초기 데이터 양 자체는 여전히 크므로 저사양 기기와 느린 연결에서 지연이 완전히 없어졌다고 단정하지 않는다.
